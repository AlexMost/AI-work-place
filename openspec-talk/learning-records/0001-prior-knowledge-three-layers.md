# Стартовий рівень: OpenSpec використовується активно, але internals — ще не власне знання

Учень активно користується OpenSpec 1.3.x + схемою `superpowers-bridge` (продакшн-репо `~/git/svadlenka-crm`) і готує доповідь про це. АЛЕ: трирівнева модель у `demo.md` («слеш-команди = markdown; CLI = детермінований state machine; instructions = prompt compiler») сформульована агентом у попередній сесії, НЕ учнем — учень явно це уточнив. Тобто теза доповіді поки не є засвоєним знанням учня.

**Evidence**: пряме уточнення учня: «demo.md сформулював не я».

**Implications**: стартувати треба саме з трирівневої моделі — але одразу на рівні сирців (senior TS-інженер, «як користуватись» вчити не треба). Мета уроку 1: щоб учень міг САМ відтворити і захистити тезу власного демо. Відкриті питання учня: (а) казав «openspec.yaml» — насправді конфіг це `openspec/config.yaml`; (б) на якому шарі інжектиться TDD в apply-фазу; (в) як механічно працює superpowers-bridge.
