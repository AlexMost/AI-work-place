Глосарій

ТермінЗначення
схема (schema)YAML-визначення workflow: артефакти + DAG залежностей + інструкції + templates + блок apply. Built-in: spec-driven.
артефактВузол DAG: {id, generates, description, template, instruction, requires}. Завершеність = існування файлів за патерном generates.
зміна (change)Тека openspec/changes/<name>/ з артефактами + метадатою .openspec.yaml.
applyФаза імплементації. НЕ артефакт: окремий блок схеми {requires, tracks, instruction}.
tracksФайл прогресу apply (зазвичай tasks.md), парситься чекбокс-regex-ом.
prompt compilerНеформальна назва openspec instructions: детермінована склейка schema + template + config у промпт.

Секції промпта — порядок і джерела

#СекціяДжерело
1<artifact id change schema>CLI-аргументи + метадата
2<warning> (якщо blocked)граф
3<task>schema: description
4<project_context>config: context
5referenced storesconfig: references
6<rules>config: rules[artifactId]
7<dependencies>граф + fs (done/missing)
8<output>schema: generates → шлях

10<template>файл templates/… зі схеми

Стан

  • Стан = файлова система. detectCompleted (state.ts:14) → artifactOutputExists (outputs.ts:40) → fast-glob по generates.
  • blocked = будь-який requires не завершений.
  • Прогрес apply: regex /^[-*]\s*\[([ xX])\]\s*(.+)\s*$/ (instructions.ts:305) — тому тільки строгий формат - [ ].

Apply: правда про інжекцію

generateApplyInstructions (instructions.ts:331-433) читає лише schema.apply. readProjectConfig() НЕ викликається → context:/rules: з config.yaml в apply-промпт не потрапляють. Прямий вхід у apply один — apply.instruction схеми. Непрямий — через контент артефактів (напр. rules.tasks формує tasks.md, який apply читає).

CLI-команди для «подивитись»

openspec status --change <n> [--json]     DAG: done/ready/blocked
openspec instructions <a> --change <n>    скомпільований промпт (є --json)
openspec instructions apply --change <n>  apply-промпт + прогрес tasks
openspec schema which <name> [--all]      звідки резолвиться + shadowing
openspec schema fork <src> [name]         копія built-in у openspec/schemas/
openspec schema validate <name>           структура + існування templates
openspec templates · openspec schemas     шляхи темплейтів · список схем
