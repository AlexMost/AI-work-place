TypeScript Generics — шпаргалка

Generic — це параметр для типів. Як функція приймає значення, generic приймає тип.

Ментальна модель

  • <T> — змінна типу. Її значення підставляє викликач, найчастіше автоматично (inference).
  • Generic зберігає зв'язок між входом і виходом. any цей зв'язок руйнує.
  • Літери — лише конвенція: T (Type), K (Key), V (Value), E (Element). Можна будь-яку назву.

any vs generic

// any — губимо тип: TS більше не знає, що повернулось
function first(arr: any[]): any { return arr[0]; }
const x = first([1, 2]);   // x: any  ← інформація втрачена

// generic — зберігаємо тип
function first<T>(arr: T[]): T { return arr[0]; }
const y = first([1, 2]);   // y: number  ← T виведено як number

Inference (виведення)

У 90% випадків не пиши тип явно — TS виведе його з аргументів. Явне first<string>([...]) потрібне лише коли вивести нема звідки.
first([1, 2]);          // T = number   (виведено)
first(["a", "b"]);      // T = string   (виведено)
first<boolean>([]);     // T = boolean  (явно — бо з [] не вивести)

Constraints — extends

// "T — будь-що, що МАЄ .length"
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}
longest([1], [1,2]);   // ok: масиви мають length
longest(1, 2);          // помилка: у number нема length
  • extends = «щонайменше ось такий». Звужує, що дозволено підставити в T.
  • Без constraint всередині функції з T можна робити майже нічого — TS не знає його форми.
  • <K extends keyof T> — класика: ключ, що точно існує в об'єкті T.

Дефолти і кілька параметрів

type ApiResult<T = unknown> = { data: T; error?: string };
function pair<A, B>(a: A, b: B): [A, B] { return [a, b]; }
pair(1, "x");   // [number, string]

Пастки

  • Зайвий generic. Якщо T вживається лише раз — він, мабуть, не потрібен (це просто заміна unknown).
  • any замість generic. Сигнал, що губиш типи. Запитай: чи має вихід залежати від входу?
  • Constraint занадто широкий/вузький. Бери рівно те, що використовуєш у тілі функції.
