Анатомія одного футболіста

Кожен біжун у гонці пулу — це не модель, завантажена з файлу, а фігурка, зібрана з примітивів у коді. Цей урок дає тобі ментальну модель, з якою ти прочитаєш функцію makeRunner() рядок за рядком.

Ціль уроку: після нього ти зможеш подивитися на торс і голову біжуна на екрані й точно сказати, який рядок коду їх створив і з чого вони складаються.

Одна ідея, з якої виросло все: Mesh = Geometry + Material

У three.js усе видиме — це Mesh (меш). А меш — це завжди дві окремі речі, склеєні разом[1]:

  • Geometry — лише форма: набір вершин. Сама по собі невидима. Це «куля», «капсула», «коробка».
  • Material — лише вигляд поверхні: колір, блиск, текстура.

Форма + вигляд = видимий об'єкт. Це як «контур фігури» та «чим його зафарбувати» — два незалежні рішення. Той самий SphereGeometry можна пофарбувати білим (м'яч) чи неоновим (голова).

// торс: капсула (циліндр з півсферами на кінцях)
const torso = new THREE.Mesh(
  new THREE.CapsuleGeometry(0.26, 0.7, 4, 8),  // ← форма
  mat);                                          // ← матеріал (колір гравця)

Аргументи CapsuleGeometry(radius, length, …): радіус 0.26, «зріст» циліндричної частини 0.7. Останні два числа — скільки сегментів (гладкість). Менше сегментів = гранчастіше й дешевше.

Друга ідея: граф сцени (Group — це контейнер)

Окремі меші треба згрупувати, щоб футболіст рухався як одне ціле. Для цього є Group — об'єкт без власної форми, просто контейнер. Головне правило графа сцени: діти позиціонуються відносно батька. Рухаєш групу — рухаються всі діти разом, як колеса разом з машиною[2].

const g = new THREE.Group();              // контейнер = «один футболіст»
torso.position.y = 1.25; g.add(torso); // торс на висоту 1.25
const head = new THREE.Mesh(new THREE.SphereGeometry(0.30, 16, 16), mat);
head.position.y = 1.95; g.add(head);   // голова — куля, ще вище

Зверни увагу на .position.y. У three.js вісь Y дивиться вгору, тому y = 1.25 і y = 1.95 ставлять торс і голову на потрібну висоту всередині групи. Коли пізніше код посуне всю групу вздовж доріжки (g.position.x = …, дистанція = бали гравця), торс і голова поїдуть з нею автоматично — бо вони її діти.

Чому фігурки світяться, хоча матеріал «базовий»?

Матеріал тут — MeshBasicMaterial. Важлива деталь: він ігнорує світло — завжди показує свій плаский колір[3]. То звідки неонове свічення? Не від ламп, а від bloom — постобробки, що розмиває яскраві пікселі в ореол. Світло у сцені є, але для неону відповідає саме bloom. Це окрема тема (урок 4), поки досить знати: колір = матеріал, свічення = bloom.
